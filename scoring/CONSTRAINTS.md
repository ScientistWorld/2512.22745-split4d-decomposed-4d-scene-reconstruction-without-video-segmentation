# Scientist Constraints

## Data
Use only the deterministic `linear_motion` and `interaction_motion` scenes generated by `data/split4d_synthetic.py` for accepted scored experiments. Do not add external videos, extra object labels, or additional generated test scenes to `scoring/scores.json`, because the scaled claim is evaluated under fixed inconsistent-mask supervision rather than by expanding the dataset.

## Evaluation Artifacts
Predictions must include primitive-level instance labels and per-primitive representation vectors in the same JSON structure consumed by `eval/metrics.py`. Do not modify ground-truth `object_id`, `dynamic_object`, or metric definitions.

## Resource Scale
Use the provided fixed primitive geometry for each scene. Do not increase the number of primitives, frames, views, or output representation dimension for scored comparisons, because that would improve the result by changing benchmark resolution rather than scientific method.

## Supervision
Candidate methods may use only the benchmark-provided observations, inconsistent mask ids, and public per-element metadata. Do not train from the hidden `object_id` labels or use them for model selection; they are evaluation labels only.

## Compliance Checklist
- [ ] Scored experiments use only `linear_motion` and `interaction_motion` from `data/split4d_synthetic.py`
- [ ] The candidate/reference comparison uses both output artifacts on the same `interaction_motion` scene
- [ ] Primitive count, frame count, view count, and output representation dimension are unchanged for scored runs
- [ ] Evaluation labels are not used during training or hyperparameter selection
- [ ] `eval/metrics.py` and the metric formulas are unchanged
- [ ] Outputs follow the JSON contract read by `scripts/evaluate.sh`
